# 3 分钟演示脚本（车间运维 AI 智能体）

> 适用场合：路演 / 参赛 / 客户汇报 / 内部评审。全程只用一个浏览器页面。
> 演示前务必按「第 0 节」准备好；每个步骤都标了**屏幕应出现的结果**，对不上就走「失败预案」。

---

## 0. 演示前检查（正式开始前 5 分钟做完）

| # | 检查项 | 命令 / 动作 | 通过标准 |
|---|---|---|---|
| 1 | 服务已起 | `python scripts/run_web.py` | 终端无报错，出现 uvicorn running |
| 2 | 页面能开 | 浏览器打开 `http://127.0.0.1:8000` | 三区布局出现，顶部状态条显示「3 台设备全部正常」 |
| 3 | 接口健康 | 新标签页打开 `http://127.0.0.1:8000/api/health` | 返回 `{"status":"ok",...}` |

| 5 | 浏览器就绪 | 用 Chrome/Edge；窗口最大化（≥1280px 宽）；关掉无关标签页 | 无其他窗口抢镜 |
| 6 | 兜底就绪 | 录屏文件放在桌面；`docs/screenshots/` 26 张截图可随时打开 | 断网等意外时 10 秒内可切换 |
| 7 | 麦克风（可选） | 演示语音输入需 Chrome/Edge 并授权麦克风；**不演示语音则跳过此项**（返工轮实测：无外网环境识别服务不可达，语音演示建议跳过，打字输入效果相同） | 点了🎤有反应（有外网时） |

## 2. 逐分钟脚本

### 0:00–0:25 ｜ 开场 + 正常态

**做什么**
1. 指着屏幕顶部状态条：「各位看这个页面——这是我们给中小加工厂做的设备运维智能体。」
2. 手指从左到右划过三个区域：「左边是产线上每台设备的心跳，右边是操作工说话的地方，顶部一句话告诉你全厂状态。」
3. 点一下左侧任意设备摘要行：「右侧滑出详情抽屉——每台设备的每个监测点、阈值、报警线、趋势、最近运维历史都在这儿，2 秒刷新；一行一台设备，30 台也不缩放不分页。」

**说什么（参考话术）**
> 「中小加工厂最常见的场景是：操作工发现机器不对劲，但说不清哪里坏了；老师傅的经验在脑子里，年轻工人问不到；出了问题停机半天，损失几千块。
> 这个系统就是解决这件事：**工人说一句大白话，系统给出结论、证据和分级处置步骤，而且只读诊断——它没有任何权限动你的设备**。」

**屏幕应出现**
- 顶部状态条：「产线状态：3 台设备全部正常」（绿色）
- 左侧三行摘要（CNC-01 / CNC-02 / AIR-01），状态灯+状态文字+关键值+迷你趋势线，读数每 2 秒微动（带噪声的真实感）
- 点击任意行，右侧滑出详情抽屉：全部监测点、阈值说明、各测点趋势、最近 5 条运维历史

---

### 0:25–0:50 ｜ 演示模式注入故障

**做什么**
1. 点顶栏「演示模式」开关 → 注入面板出现；
2. 设备选 **CNC-01**，故障选 **主轴过热**，点「注入故障」；
3. 停顿 2 秒，让屏幕自己说话。

**说什么**
> 「我现在通过演示模式给一号机注入一个主轴过热故障——注意看顶部。」

**屏幕应出现**
- 顶部状态条**整条变红**：「产线状态：3 台设备中 1 台报警」
- 左侧 CNC-01 摘要行**自动置顶 + 红色高亮**（带未处理报警数角标），主轴温度读数冲上 85℃ 以上
- 报警出现耗时约 1–2 秒（验收标准：10 秒内）

**关键点（评委在意）**：报警不是写死的——是系统按「阈值 + 回差 + 连续周期去抖」从数据里推出来的，所以恢复时也不会在阈值附近抖动。

---

### 0:50–1:35 ｜ 口语诊断（核心环节）

**做什么**
1. 在右侧输入框打字（**故意打成口语**）：「一号机主轴发烫，温度高得厉害」→ 点「诊断」；
2. 等报告出来（<2 秒），手指点三处：**第一行结论 → 证据火花线 → 分级清单**；
3. 点结论旁的 **F001 角标**：「这个编号直接对应知识库条目，点开就是原文——结论可溯源。」

**说什么**
> 「注意，操作工不需要懂任何参数，就说'发烫、温度高'。系统做了四件事：
> 第一，**结论先行**——一号加工中心，主轴温度过高，置信度中等；
> 第二，**证据可读**——实测 87 度对阈值 80 度，这条火花线能看到是从什么时候开始超标的；
> 第三，**分级处置**——绿色是操作工自己能干的，黄色要维修工，红色必须工程师；
> 第四，**可溯源**——每一步都带知识库编号，不是大模型编的。」

**屏幕应出现**
- 报告卡第一行即结论：「一号加工中心 · 主轴温度过高（F001，置信度 中）」
- 证据条目：实测值 vs 阈值 + 偏差百分比 + 迷你趋势线
- 步骤按 L1（绿）/ L2（黄）/ L3（红）分组，每步带工具/物料/预计耗时
- 点 F001 角标弹出知识库条目详情

---

### 1:35–2:05 ｜ 排查模式 + L3 安全确认（安全亮点）

**做什么**
1. 点报告卡底部「▶ 开始排查（单步模式）」；
2. 屏幕进入全屏单步：「一次只显示一步，三个大按钮——上一步、完成下一步、退出。车间戴手套也能点。」
3. 一路点「完成，下一步」走到 L3 步骤 → **弹出红色安全确认层**；
4. **先不勾选**，点确认按钮 → 演示「不过去」；再勾选「我已断电挂牌上锁（LOTO）」但**不填确认人** → 仍然不过去；最后填写持证人员姓名/工号 → 才进入 L3，弹层提示「安全确认已留痕」。

**说什么**
> 「为什么危险的活儿要工程师？因为系统把涉及带电、高压、拆机的步骤**强制标成 L3**，这是写在代码里的安全闸，大模型也无权降级。
> 进入 L3 之前必须勾选 LOTO 声明**并由持证人员署名**，这个校验在服务端：未经确认时，就算绕开页面直接调接口把这一步标记完成，也会被 400 拦下，确认人和时间落库可查。
> 但我要主动说清楚：**这是人工确认，不是系统检测到设备已断电**——我们只读，拿不到主电源和挂锁状态，也不装作能判断。物理安全由设备侧硬回路和现场 LOTO 规程承担，我们只保证流程不被跳过、责任能追到人。」

**屏幕应出现**
- 全屏单步界面，显示「第 X 步 / 共 N 步」进度
- L3 步骤红色边框 + 警示图标 + 大字 + 「未完成安全确认」提示
- 红色安全确认弹层：黄色提示条写明「系统未接入断电/挂锁信号，无法检测是否真的断电」；未勾选或未署名时确认按钮禁用；署名成功后进入 L3 并显示确认留痕

---

### 2:05–2:35 ｜ 反馈 + 历史 + 经验沉淀 + 导出

**做什么**
1. 退出排查模式 → 在报告卡底部点「✅ 已解决」→ 出现「已记录」提示；
2. 点顶栏「历史」→ 刚处置的记录已在列表里（点开可看当时的证据快照和勾了哪些步骤）；
3. 点顶栏「经验」→ 指着复发提醒和统计卡：「哪台设备、哪个故障、坏几次、平均处理多久、累计停机多久——老板视角一屏看完。」
4. 点「⬇ 导出 Excel」→ 文件下载完成（如时间紧，此步可只说「一键导出给老板」不真下）。

**说什么**
> 「每一次'已解决'都进了记忆库，而且必须署名处理人、停机时长是自动计时的——从设备报警那一刻起表，到点'已解决'停表，直接进停机统计。
> 第二次同样故障，系统会主动引用上次怎么处理的。
> 经验页按设备统计高频故障、平均处理时长、累计停机；同一台设备 30 天内同一故障出现两次以上，系统自动提醒——**这是在帮工厂把老师傅的经验变成数据资产**。
> 停机统计一键导出 Excel，工厂老板不看系统也能看报表。」

**屏幕应出现**
- 点「已解决」后出现成功提示「已记录：本次处理有效，下次会优先推荐。」（若操作人为空会先被拦截：「请填写操作人姓名/工号（必填）」）
- 成功提示带停机时长：「…停机 N 分钟…」（设备报警起自动计时，确认解决停表）
- 历史页列表出现该记录（含结果徽标「✅ 已解决」）
- 经验页：统计卡（记录数/解决率/累计停机）+ 复发提醒卡 + 按设备高频故障条形图
- 点击导出后浏览器开始下载 `运维记录与统计_YYYYMMDD.xlsx`

---

### 2:35–3:00 ｜ 收尾

**说什么（参考）**
> 「总结三个数字：诊断从'说人话'到出结论 **2 秒以内**；报警检出 **1–2 秒**（标准是 30 秒）；处置步骤 **100% 来自知识库原文**，可溯源、可审计。
> 我们的路线是：现在是仿真产线验证，下一步接**半真实只读网关**读真设备数据，再扩展到注塑机、冲床等其他品类。
> 这是个只读、安全、能把每次运维变成资产的系统。谢谢各位。」

**做什么**：停在监控页（三台设备恢复绿色状态亦可，若前面点了「全部恢复」）。

## 3. 失败预案（每步的备用话术）

| 环节 | 可能失败 | 现场处置 | 备用话术 |
|---|---|---|---|
| 开场 | 页面打不开 / 白屏 | 直接切录屏；同时让同事看服务终端 | 「现场网络问题，我放一段 3 分钟实录，流程完全一致」 |
| 注入 | 面板不出现 / 注入没反应 | 检查「演示模式」开关是否真的打开；仍不行则用 CLI 注入（同事提前在第二终端待命：`python -m cncops inject --device CNC-01 --fault spindle_overheat`） | 「这是演示开关，生产环境这个入口是关闭的——正好说明注入是受控的测试夹具」 |
| 注入后 | 报警摘要行没置顶 | 等 2 秒（数据 2 秒刷新 + 去抖周期）；仍不行就刷新页面 | 「大家注意顶部这句话——全厂状态一句话说完，这是 HMI 的第一原则」 |
| 诊断 | 报告不出 / 转圈 | 看 `/api/health`；超时则用 CLI 版结果（`docs/demo_output.txt` 已存档） | 「我把完整诊断输出投出来，内容与界面完全一致」 |
| 诊断 | 结论不是我讲的故障 | 顺势讲「误报回归」：自测里有 6 条误报回归用例，每个故障与报警码一一对应，这是验收过的 | 「这正好是我们重点验收的部分——过热不许被报成闷车，自测里有专门回归」 |
| L3 确认 | 弹层没出现 | 检查是否走完了 L1/L2；直接点步骤列表里红色 L3 步骤 | 「安全确认是强制的，绕不过去——这正是设计目标」 |
| 反馈 | 点了没提示 | 刷新页面后点历史页验证；用 CLI `python -m cncops feedback <id> --resolved` | 「记录已经落库，我打开历史页给大家看」 |
| 导出 | 下载被浏览器拦截 | 点浏览器地址栏右侧的拦截提示允许下载；或提前下好一份放桌面 | 「文件已经准备好了，这是导出的样子」 |
| 断网 | 页面显示「数据连接中断」 | **不要慌**——这正是设计行为，拿它当卖点讲 | 「大家看到'数据连接中断'——系统宁可停下说连不上，也绝不显示过期数据冒充正常」 |
| 整体崩 | 任何环节连续失败 | 切录屏（10 秒内），按脚本继续讲解 | 「以实录为准，现场环境问题」 |
