# 第一部分 · 需求背景

## P3 · 行业痛点（为什么值得做）

- **5 大痛点**（用对比表或 5 个图标卡）：
  1. 会说的不会修、会修的不在 → 小故障拖成大停机
  2. 经验锁在老师傅脑子里 → 人走技失
  3. MES 看得见、看不懂 → 数据在、决策不在
  4. 通用聊天机器人不敢用 → 会编步骤、没安全边界
  5. 停机账算不清 → 改善没抓手
- **市场侧写**：中国中小加工厂数十万家，设备运维高度依赖个人经验；一次主轴抱闸停机损失数千到数万元，而"能说话的知识库 + 只读诊断"年费仅数千元 → **ROI 一次停机就回本**。
- **视觉**：左侧 5 个红色痛点卡，右侧一个绿色"ROI 一次停机回本"大数字块。
- **话术**："MES 告诉你发生了什么，聊天机器人陪你聊发生了什么——我们告诉你现在该干什么。"

## P4 · 目标用户与典型场景

- **三类使用者**：操作工（开机旁，做 L1）、维修工（随叫随到，做 L2）、运维负责人（看经验沉淀与停机统计）。
- **典型场景**：夜班突发报警、老师傅请假、新工人不敢拆机、老板想知道"哪台最爱坏"。
- **视觉**：一张"人—角色—系统给什么"的三行对照表（或三头像 + 气泡）。

## P6 · 整体技术架构（分层）

- **四层架构**（画分层架构图）：
  - 车间 HMI（原生 HTML/CSS/JS，深色工业风，无构建步骤）
  - Web API 层（FastAPI + uvicorn，18 个路由）
  - 诊断智能体（固定六步工作流）
  - 数据源 / 知识库 / 记忆库 / 大模型（可选）
- **视觉**：架构图（参考 `项目总结与使用说明.md` §4.1 文字架构图，转成图形）。
- **话术**："后端、前端、数据库、知识库，全部本地一套，不依赖云。"

## P7 · 核心诊断引擎（固定六步）

- **固定六步，不用大模型也能跑**（横向流程图）：
  1. 口语解析（设备别名 + 同义词，确定性）
  2. 取实时数据（仿真器 / OPC-UA 只读）
  3. 阈值比对生成证据（报警码由"阈值+回差+去抖"推导，不写死）
  4. 知识库三路检索（字面 + 本地 TF-IDF + 结构化，Top-3）
  5. 历史复发引用（同故障主动提上次怎么处理）
  6. 固定七段格式渲染（结论/证据/原因/步骤/警告/来源/历史）
- **视觉**：6 个节点横向箭头流程图，强调"无 LLM 也完整可用"。
- **话术**："大模型是锦上添花，不是雪中送炭——它挂了系统照样出报告。"

## P8 · 技术选型（轻量、离线）

- **技术栈表**（强调"轻、离线、零配置"）：
  - 后端：Python + FastAPI + uvicorn
  - 前端：原生 HTML/CSS/JS，无框架、无构建
  - 数据库：SQLite（自动创建，零安装）
  - 知识库：YAML 文件（厂内技术员可维护）
  - 检索：本地 TF-IDF 余弦（纯 Python，完全离线）
  - 大模型：OpenAI 兼容协议，Key 只走环境变量，可选
- **视觉**：技术栈卡片墙，每张卡一个技术 + 一句话卖点（轻/离线/可改）。
- **话术**："一台旧电脑 + 浏览器就能跑，不需要 GPU、不需要服务器集群。"

## P9 · 安全设计（只读红线 + L3/LOTO）★ 重点页

- **只读是铁律**：OPC-UA 客户端无任何 write 方法，有回归测试守着；界面无"启动/停机/改参数"按钮；"注入故障"只是改仿真器的演示夹具。
- **安全闸在代码里**：涉及带电/高压/拆机的步骤强制升 L3 + 安全警告，位于渲染链最后一步，**LLM 无权降级**；进 L3 前强制 LOTO 安全确认（遮不掉、跳不过）。
- **可视化**：配 `docs/screenshots/`（L3 红色安全确认弹窗）或自绘"危险词 → 强制 L3 → LOTO 确认"决策图。
- **话术**："敢把系统搬进车间，靠的就是这两条：永远不碰设备，危险步骤必须人确认。"

## P10 · 大模型增强与降级模式

- **大模型是可选增强**：只负责口语理解补充、原因排序与语言组织；排查步骤**恒取自知识库**，模型不生成步骤。
- **自动降级**：无 Key / 超时（8s）/ 输出未通过校验 → 回退规则版，七段格式不变，断网可演示、离线可交付。
- **已真实验证**：2026-10-27 用真实 DeepSeek（deepseek-chat）实跑，**20/20 链路断言通过、11/11 类故障均被模型改写结论并产出 narrative、响应无控制类字段**。
- **视觉**：一张"增强模式 vs 降级模式"双栏对比卡 + 一个 `20/20` 大数字徽标。
- **话术**："配了模型，报告更会说人话；不配，结论一样准——这就是我们敢说安全的原因。"

## P13 · 现场实操演示脚本（3 分钟）

- **演示三步**（直接对应 `docs/DEMO_3MIN.md`）：

## P14 · 经验沉淀闭环（记忆库 / 复发提醒）

# 第四部分 · 价值与落地

## P15 · 和传统运维的对比 ★ 差异化页

- **核心对比**（横/纵对比表，左列"传统运维（人 + MES）"、右列"cncops-agent"）：
  | 维度 | 传统运维（人 + MES） | 本项目 cncops-agent |
  |---|---|---|
  | **故障发现** | 人工巡检 / 等人报修，滞后 | 实时自动监测，报警自动置顶变红 |
  | **诊断依据** | 靠老师傅经验，人不在就抓瞎 | 2 秒出结论 + 实测值 vs 阈值证据 |
  | **步骤来源** | 凭记忆 / 厂商手册，无溯源 | 知识库原文，每步带编号可查 |
  | **安全边界** | 靠自觉，带电作业有风险 | L3 强制升级 + LOTO 代码闸门 |
  | **经验留存** | 人走技失 | 记忆库沉淀，复发自动提醒 |
  | **停机账** | 老板算不清 | 自动计时 + 经验页统计导出 |
  | **离线可用** | 依赖人在现场 | 无 Key 自动降级，完全离线可跑 |
- **一句收口**：MES 告诉你"发生了什么"，聊天机器人"陪你聊发生了什么"，我们告诉你"**现在该干什么、谁来干、怎么干才安全**"。
- **视觉**：左右双栏对比卡（左灰右青），最后一行"离线可跑"放大成强调块；或七行对照表，右侧青色"我们"列整列高亮。
- **话术**："我们不是替代维修工，是给维修工配一个不会累、不会走、随时在线的老师傅。"

## P16 · 产业场景落地价值

- **谁最该用（适用场景）**：
  - 中小机加工厂（CNC 加工中心、空压站）：无专职设备工程师，靠"操作工 + 维修工"两人兜底
  - 夜班 / 无人值守时段：突发报警无人判断
  - 老师傅断层：年轻人"不敢问、记不住"
  - 多品类延展：注塑 / 冲床 / 压铸（路线图 ③）
- **落地路径（低风险渐进）**：
  - ① 仿真产线验证（**已交付**）→ ② 半真实只读网关（接真机 OPC-UA 只读，零风险试点）→ ③ 多品类扩展 → ④ 生态
  - 任何阶段保持**只读**，厂长敢签字
- **落地价值（定性量化）**：
  - **ROI 一次停机就回本**：年费数千元 vs 一次主轴停机损失数千到数万元
  - **覆盖 80% 常见故障**：两个人 + 一个系统兜底，L3 才花钱请外援
  - **经验资产化**：用得越久历史数据越值钱，迁移成本越高 → 续费黏性
  - **离线可交付**：内网 / 断网 / 评委离线都能跑，数据不出厂
- **视觉**：左侧"适用场景"三图标卡 + 右侧"落地路径"时间轴（① 高亮"已交付"）+ 底部一条"ROI 一次停机回本 / 覆盖 80% / 离线可交付"三个价值徽标。
- **话术**："我们先不碰真设备就能证明全链路可靠；等厂长愿意了，再用只读网关接一条线——零风险把价值落地。"

# 收尾

## P17 · 商业模式（SaaS 订阅）

- **收费逻辑**：按"接入设备数 + 账号数"分档，经验沉淀与报表是续费核心。
- **三档**（对比表）：免费版（≤5 台，获客）｜ 专业版 **¥6,800/年起**（主力，自定义知识库 + 完整台账）｜ 企业版 **¥30,000/年起**（私有化 LLM + 多租户）。
- **转化路径**：免费版用"10 秒看报警"留住操作工 → 30 天历史用完时厂长已在经验页看到停机账 → 升级专业版。
- **视觉**：三档定价卡（免费/专业/企业）+ 一条"免费→付费"转化漏斗。
