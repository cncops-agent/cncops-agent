## ② 新结构说明

### 页面骨架（桌面）

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶部状态条：产线一句话总览 + 时间（报警整条变红） ← 固定             │
├────────────────────┬─────────────────────────────────────────────┤
│ 设备状态（列表头）   │ 这台机器怎么了？输入区                       │
│ 共 N 台·报警 x·…   │                                             │
│ ┌─────────────────┐│  诊断报告区（结论先行 / 证据 / L1-L3 步骤 /   │
│ │全部(30) 只看报警(1)││  单步排查 / 反馈）                        │
│ │只看预警(0) 只看正常(29)│ [搜索设备编号/名称] │  ← 筛选条固定      │
│ ├─────────────────┤│                                             │
│ │🔴 报警 CNC-06 …││  ← 抽屉打开时右侧照常显示，不重排、不挤压      │
│ │🟡 预警 AIR-03 …││                                             │
│ │🟢 正常 CNC-01 …││                                             │
│ │   …            ││                                             │
│ └─────────────────┘│                                             │
│   （仅此区域滚动）   │                                             │
└────────────────────┴─────────────────────────────────────────────┘
        点击任意行 → 右侧滑出 460px 详情抽屉（遮罩 + 滑入动画）
```

### 摘要行（一行一台设备，56px 固定）

| 元素 | 规格 |
|---|---|
| 状态灯 + 状态文字 | 12px 圆点（绿/黄/红/灰）+ 14px 加粗文字「正常/预警/报警/中断」，颜色文字双通道，不单独依赖颜色 |
| 编号 + 名称 | 14px，编号加粗等宽数字，超长省略 |
| 唯一关键监测值 | 16px 加粗：CNC 显主轴温度、空压机显排气压力（由 `dev.key_point_keys` 驱动）；超标变红并标注「上限 XX」/「下限 XX」，预警琥珀色标注「注意 XX」；**一行只有这一个数值** |
| 迷你趋势线 | 76×40 SVG 火花线 + 红色虚线报警阈值，数据源 `/api/trend` 与抽屉同缓冲 |
| 报警角标 | 红色圆形数字 = 未处理报警数；**无报警不渲染**（实测全正常时角标数=0） |

### 排序与筛选（每轮刷新实时执行）

- 排序：报警 > 预警 > 离线 > 正常，同级按设备编号 `localeCompare`；注入后下一轮刷新即重排
- 筛选条固定不随列表滚动：全部 / 只看报警 / 只看预警 / 只看正常，各带实时数量；搜索框按编号或名称过滤；无结果有空态「没有符合筛选条件的设备」
- `filter`/`keyword` 是应用级状态，轮询刷新不重置

### 详情抽屉

- 桌面：右侧滑出 **460px**，`transform` 过渡 0.28s，遮罩淡入；**右侧主区宽度不变、内容不重排**；`body.drawer-open` 锁定底层滚动
- 内容：当前报警列表 → 全部监测点（实时值+单位+严重度图标+「注意 X / 超标 Y（越高/越低越危险）」阈值说明）→ 各测点趋势图（两列网格，虚线为报警阈值）→ 最近运维历史（≤5 条，含结论/时间/结果/操作人/备注，空态有提示）→ 底部「💬 对该设备提问诊断」
- 三种关闭：右上角「✕ 关闭」按钮 / 点抽屉外遮罩 / Esc 键
- 手机端（≤900px）：抽屉 `width:100%` 全屏，趋势图单列
- 抽屉打开期间：每 2 秒轮询同步刷新（`drawerSub` 更新时间戳推进，滚动位置保持，设备不丢失）

### 数据与断线语义（与列表同源同周期）

- 刷新周期 2 秒（`POLL_MS=2000`，符合 2~5 秒要求）：`/api/line` + 各设备 `/api/trend/{id}?n=24` 并行，抽屉详情走 `/api/devices/{id}` + `/api/history?limit=5`
- 接口异常：顶部「⚠ 数据连接中断」横幅 + 所有行的关键值清空为 `--`（保留设备骨架行）+ 抽屉显示中断提示，**绝不静默显示过期数值**；恢复后横幅自动消失、真实数值回来

### 五条禁令落实

| 禁令 | 落实 |
|---|---|
| 禁 `transform:scale/zoom` 缩放适配 | 未使用任何缩放；实测行/body/layout 的 `transform` 均为 `none`（3/10/30 台 + 手机端均断言） |
| 禁减小字体压缩行高 | 行内字号 ≥14px（名称/状态 14px、关键值/行主体 16px），行高固定 56px（规格 56–64px 内），不随设备数变化 |
| 禁行内堆多测点 | 每行只渲染 `key_metrics[0]` 一个关键值（验收断言「每行只有一个关键监测值」通过） |
| 禁分页 | 无分页控件；30 台全部渲染，列表内部滚动 |
| 禁挤压右侧诊断区 | 设备列固定 480px，抽屉为 `position:fixed` 浮层；实测抽屉打开期间右侧列宽度与内容不变 |

### 2. 一屏 ≥12 行 —— ⚠️ 部分达标（容量达标，10 台档按口径说明）

- **30 台档实测：一屏可见 14 行**（列表视口高 840px，30 行内容高 1800px，列表独立滚动 `scrollH=1800 vs clientH=840`）→ 行容量 ≥12 行的要求达标。

- 3 台档：3 行全见，列表不产生滚动（`scrollH=840 = clientH=840`）。
- 说明：≥12 行是「行容量」要求，本项以 30 台档的 14 行/屏作为容量证据；10 台档受设备总数限制只能显示 10 行，这是配置事实而非布局缺陷。**不删验收项、不改配置虚报行数。**

## 如实标注的已知限制

1. **headless `mobile:true` 模拟错位（环境产物，非产品缺陷）**：CDP 的 `Emulation.setDeviceMetricsOverride` 带 `mobile:true` 时，`innerWidth`(435) 与布局宽度(390) 不一致，导致 `position:fixed` 包含块偏移 45px（抽屉 left=45）。手机端验收改用 `mobile:false` 纯视口宽度（390×844）模拟，实测抽屉 left=0/right=390 完全全屏；文档宽度、媒体查询、抽屉 CSS 宽度在三者下均正确为 390px。真实手机浏览器不存在该错位。
2. **10 台档「一屏 ≥12 行」口径**：如第 2 条所述，10 台配置共 10 台设备，一屏 10 行即全部；行容量证据取自 30 台档（14 行/屏）。
3. **30 台档抽屉历史为 0 条/空态**：验收用临时记忆库中 AIR-01 等设备确无诊断历史，属正确空态（「该设备暂无运维历史」），非缺陷。
4. **手机端趋势图尺寸**：390px 下抽屉趋势图由桌面两列改单列、摘要行火花线缩为 52×22px，是为固定 56px 行高内的必要适配，非缩放（`transform` 仍为 none）。
