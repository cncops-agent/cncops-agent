# cncops-agent 技术说明文档

> **项目**：中小加工厂设备运维 AI 诊断助手（只读诊断）
> **适用**：OPC 创新应用挑战赛 · AiCoding 硬核组（场景应用赛道）· 赛道参赛材料「技术说明文档」

> **配套交付物**：`cncops-demo-setup.exe`（可运行 Demo 安装包，27.4 MB）、`cncops-agent路演.pptx`（项目说明 PPT，15 页）

## 摘要

系统面向中小加工厂车间：一线人员用一句大白话描述异常（如"一号机发烫"），系统自动取设备实时数据、比对阈值生成证据、检索故障知识库、结合该设备历史，输出**结论先行 + L1/L2/L3 分级排查步骤**的诊断报告，并把每次运维沉淀成可查询、可导出的经验台账。全程**只读**，代码里不存在任何向设备下发控制指令的能力。

技术实现为「原生前端 + FastAPI 单端口服务 + 进程内仿真数据源 + SQLite 记忆库 + 可选大模型增强」，可完全离线运行；另提供 PyInstaller/NSIS 打包的 Windows 安装向导，评审机无需 Python、无需联网。

### 1.4 人工不可替代的 4 类环节与返工纠偏实例

**4 类环节**：① 业务规则设计（11 类故障剧本、阈值与回差、F001–F006 / F101–F104 编号体系、L1/L2/L3 分级）；② 验收标准设计（六条验收铁律、报告卡七块结构、逐故障 Top-1 回归口径）；③ 放行决策（通过 / 有条件通过 / 不通过由人工判定）；④ 秘密管理与合规口径（API Key 只走环境变量、不落盘、不入库）。

**有代表性的返工纠偏（人工质疑 → AI 重做 → 人工复验）**：

| 人工提出的质疑 | 最终技术处理 |
|---|---|
| 「我们检测设备断电吗？没做到就不能这么写」 | 把 L3 明确改写为**人工署名确认 + 服务端强制校验 + 落库留痕**，页面与文档统一标注「非系统检测断电」「系统未接主电源/挂锁信号」；物理安全交由设备侧硬回路与现场 LOTO 规程 |
| 「员工没断电直接勾选操作框怎么办」 | 新增 `l3_acks` 表与 `/l3-ack` 接口，`save_checklist` 整体前置校验，未确认的 L3 勾选返回 **400 且不落库**，绕开前端直接调接口同样被拦；自测 M 段 6 项守门 |
| 「打开 exe 不跳浏览器」 | 子线程 COM 初始化 + `os.startfile` → `webbrowser` → `cmd /c start` 三重兜底，成功/失败原因打印到控制台，健康检查最长等待 30s |
| 「一注入故障步骤就全勾好了、操作人默认 11」 | 定位为旧 `localStorage` 缓存与新库 id 重号串号；移除浏览器本地存储，改为服务端 `checklist` 唯一真相，注入新故障清空上一轮报告与勾选，操作人每轮本人填写 |
| 「用真实 Key 验证，但 Key 不许落盘」 | Key 仅经调用进程环境变量传入，20/20 链路断言与 11 类故障对比通过后对项目全文 grep 确认无任何密钥残留，默认回到无 Key 降级模式 |
| 「安装包形式 / 用 V2 图标 / 代码签名不搞了」 | 人工选定 NSIS 安装向导、V2 七尺寸 ICO；代码签名按人工决定明确不做，并在文档中如实标注 SmartScreen 影响 |

角色化提示词分工：开发者（可改代码）→ 独立验收员（**只检查不改代码**）→ 技术写作者（只写不改）→ 返工执行人（改动必须可验证），四角色各带只读/可改边界与"不许放水、不许编造"铁律。

### 2.2 运行环境与依赖策略

- **离线优先**：最小 CLI 链路只需 PyYAML；Web 链路加 fastapi / uvicorn / httpx。无 GPU、无向量数据库、无外部服务，LLM 与 OPC-UA 均为**可选**，缺失即自动降级。
- **真实设备通道**：`asyncua` 只读客户端 + 进程内仿真 OPC-UA 服务器（可选），接真机需配置 `CNCOPS_OPCUA_ENDPOINT` 并按现场点位扩充配置。
- **密钥管理**：`CNCOPS_LLM_API_BASE` / `CNCOPS_LLM_API_KEY` / `CNCOPS_LLM_MODEL` 等全部从环境变量或本地 `.env` 读取，代码里不出现厂商名与密钥；`CNCOPS_LLM_ENABLED=0` 可强制关闭增强。验证结束后项目不保留任何 Key，默认即为无 Key 的规则版。
- **冻结态路径**：`paths.py` 在 `sys.frozen` 时以 `sys._MEIPASS` 为资源根；数据/日志优先写 exe 同目录，若目录不可写（如安装到 Program Files）自动回退 `%LOCALAPPDATA%\cncops-demo`，保证 SQLite 可创建。

## 三、系统架构

```
车间 HMI（web/static，原生 HTML/CSS/JS，fetch JSON）
  监控（状态条 / 摘要行 / 详情抽屉 / 报告卡）｜ 历史时间线 ｜ 经验沉淀 ｜ CSV/Excel 导出
        │
Web API 层（api.py · FastAPI，单端口 8000 同时托管静态资源）
  /api/line  /api/diagnose  /api/history  /api/insights  /api/records/{id}/...
  /api/records/export  /api/demo/*（演示注入，服务端总开关）
        │
诊断智能体（agent.py，固定工作流）
  ① 口语解析 → ② 取实时数据 → ③ 阈值比对生成证据 → ④ 知识库融合检索
  → ⑤ 历史复发引用 → ⑥ 结论/原因排序（可选 LLM 增强）→ ⑦ 步骤取自 KB + 安全分级 → ⑧ 落库
        │
  ┌─────────┬──────────────┬──────────────┬────────────────┐
  数据源门面   知识库          记忆库           大模型（可选）
  simulator / config/kb/*.yaml memory.py     llm_client.py
  opcua 只读   12 条条目       SQLite 5 张表   OpenAI 兼容协议
                              多工厂/租户预留   失败自动降级
```

**只读边界**：`opcua_client.py` 不含任何 `write/set` 方法（`tests/test_safety_readonly.py` 回归该约束）；故障注入只改仿真器内部状态，属测试夹具，不下发控制指令。

## 四、核心功能实现逻辑

### 4.1 诊断主链路（`agent.py::DiagnosisAgent.diagnose`）

| 步 | 实现 | 关键设计 |
|---|---|---|
| ① 口语解析 | `parser.py` + `config/lexicon.yaml`：设备别名、同义词、危险词（冒烟/焦糊味）识别 | **确定性**解析，不依赖大模型，保证可复现 |
| ② 取实时数据 | `tools.get_device_data()` → `datasource.py` 门面（内置仿真器 / 可选 OPC-UA 只读） | 未显式指定设备时按异常分数自动选机；数据源降级会写入 `degraded_reasons` |
| ③ 阈值比对 | `rules.build_evidence()`：按 `config/thresholds.yaml` 逐测点判定 normal/warn/alarm，生成"实测值 vs 阈值 + 超出百分比"的证据文本 | 阈值**只从配置读取**，业务代码零硬编码；报警码由 `derive_alarm_codes()` 从证据**派生**，不做独立随机，保证"码与数据一致"防误报 |
| ④ 知识库检索 | `knowledge.py::search()`：字面加权（标题/症状 3.0、报警码 2.0、测点 1.5）+ TF-IDF 余弦 + 结构化（设备类型 0.35、报警码 0.3/个、测点 0.15/个）三路加权，取 Top-3 | 每条命中带 `reasons` 可溯源；`is_uncovered()` 判定未覆盖，回退通用安全条目并明确输出「知识库未覆盖」，不硬编步骤 |
| ⑤ 历史引用 | `tools.get_history()` + 故障指纹 `signature = 设备|报警码|异常测点` | 同设备 30 天内同类故障复发时引用上次处置记录；上次未解决则追加 L3 升级步骤 |
| ⑥ 结论与原因排序 | 先出**规则版**（`rank_causes` 结合基础概率、证据、历史反馈权重），再尝试 LLM 增强 | 见 4.2 |
| ⑦ 步骤与安全分级 | 步骤**恒取自知识库原文**（每步带 `kb_id`、工具/物料/耗时）；`safety.py` 用危险词表把拆机/带电/高压/主轴拆装/液压步骤强制升 L3 | 分级在渲染链最后一步确定性产出，**不受大模型输出影响** |
| ⑧ 落库与输出 | `memory.save_diagnosis()` 保存完整快照（含步骤原文）、`_report_payload()` 组装七块报告卡 | 每次诊断都沉淀，历史页可还原当时的完整勾选清单 |

### 4.2 大模型增强的边界（`llm_client.py` + `agent.py::_try_llm`）

- **能改**：`conclusion`（结论表述）、`narrative`（口语化解读）、`causes` 的**排序与依据文字**、`parsed.llm_symptoms`。
- **不能改**：排查步骤（恒取 KB 原文，每步带 `kb_id`）、安全分级、阈值、报警码、数据源。
- **校验与降级**：`_validate_llm()` 校验模型返回的 `kb_id` 必须属于本轮候选集；未配置 Key、超时、网络错误、JSON 不可解析、校验不通过，任一情况都返回 `None` 并自动回退规则版（`mode=rule`、`degraded=True`、写明原因），报告七块结构不缺。
- **控制面隔离**：增强响应不含 `command/write/setpoint/control` 字段，已列入真实模型验证断言。
- **真实模型实测**：DeepSeek `deepseek-chat` 下 20/20 链路断言通过、11 类故障均改写结论并产出 narrative；增强/降级的排查步骤完全相同（8=8），10/11 类识别同一 Top-1（1 类为原因重排观察项，结论方向一致，已如实记录）。单诊断耗时增强 3.91s / 降级 0.07s。

### 4.3 L3 服务端强制闸门（安全关键路径）

1. `safety.escalate_steps()` 用危险词表确定性把危险步骤升为 L3；
2. 前端进入 L3 前弹出确认层：勾选 LOTO 声明 + 填写持证人员姓名/工号，界面明确写「**人工确认，非系统检测**」「系统未接入主电源/挂锁状态信号」；
3. `POST /api/records/{id}/l3-ack` 校验记录存在、`step_key` 确属本次诊断的 L3 步骤（服务端从落库步骤原文还原，**不信任前端传参**）、确认人非空、`mode` 合法、`signal` 模式必填真实信号来源；通过后写入 `l3_acks` 表（确认人 + 时间 + 模式 + 信号源，唯一约束）；
4. `POST /api/records/{id}/checklist` **先整体校验再逐条写入**：本次新勾选的 L3 步骤若无对应确认记录，返回 **400 且不落库**；绕过前端直接调接口同样被拦；
5. 历史详情回显确认人与时间，可追溯。

> **诚实边界**：这是**人工署名确认 + 服务端强制校验 + 落库留痕**，**不是设备断电检测**。只读数据源拿不到主电源与挂锁状态，系统不判断设备是否真的断电；物理安全由设备侧硬接线安全回路、安全继电器、零速/无压检测与现场 LOTO 规程承担。软件输出是诊断建议，不是作业许可。

### 4.4 记忆库与经验沉淀（`memory.py`）

SQLite 5 张表：`factories`、`diagnoses`（完整诊断快照 + `tenant_id`/`factory_id`/`operator`/`alarm_codes`）、`feedback`（处理结果、操作人、处理时长、停机时长）、`step_checks`（排查勾选，服务端唯一真相）、`l3_acks`（安全确认留痕）。老库由 `_migrate()` 无感加列，所有查询带租户条件。

- **反馈闭环**：操作人必填（空值前端拦截 + 后端 400 不落库）；停机时长从报警起点自动起表、确认解决停表，停表后不重启，复发起新表。
- **经验视图**：高频故障、平均处理时长、同设备 30 天同故障 ≥2 次的复发提醒。
- **导出**：CSV（UTF-8 BOM，18 列）与 XLSX（双工作表 + 统计），后者为标准库手写 OOXML，零第三方依赖。

### 4.5 演示模式与数据隔离

`CNCOPS_DEMO_ALLOW=0` 可整体关闭演示接口（关闭时页面无注入入口）；11 类故障可注入，注入后 2s 内报警行置顶变红；注入新故障会清空上一轮报告与勾选，操作人每轮本人填写。验收脚本一律指向临时库实例，不污染正式记忆库；自测固定随机种子 `20261018`，连跑两次输出逐字节一致。

### 4.6 离线 Demo 打包

`freeze_entry.py` 先设环境变量再读配置（`settings` 有缓存），启动 uvicorn 后由守护子线程轮询 `/api/health`（最长 30s）并三重兜底打开浏览器；`cncops-demo.spec` 用 PyInstaller onedir 打包，NSIS 脚本（`Unicode true` + UTF-8 BOM）安装到 Program Files、创建桌面/开始菜单快捷方式与卸载程序。重编译后实测 `dist` 内 17 个静态资源与源码逐字节一致，V2 图标 7 个尺寸图像块原样嵌入主程序。

## 七、能力边界与未做事项（如实标注）

1. **数据为仿真数据**，未接真实产线设备；OPC-UA 只读通道连接的是进程内仿真服务器，接真机属下一阶段。
2. **知识库覆盖 11 类可注入故障**（CNC 6 + 空压机 5）、专业条目 10 条 + 2 条兜底；覆盖之外明确输出「知识库未覆盖」并只给通用安全建议，不硬编步骤。
3. **L3 不是断电检测**（见 4.3）；系统不下发任何控制指令，不替代现场安全规程。
4. **单租户单工厂运行**，多工厂/多租户仅结构预留；无登录/账号体系，操作人随反馈落库。
5. **计时与趋势为进程内状态**，服务重启后重新起表；已落库记录不受影响。
6. **语音输入**依赖浏览器 Web Speech API 与外网，离线实测录音指示正常但识别服务不可达，属环境限制。
7. **手机竖屏**已用 390×844 无头视口验收，未做真机验收。
8. **未做代码签名**（按项目决定），首次运行可能被 SmartScreen 拦截，点「仍要运行」即可；GUI 向导真实双击安装需在桌面会话人工确认。
9. 当前 PPT 工程目录 `pptx/cncops_pitch_v2/` 与部分历史验收文档中的 82/82 为**当时轮次**存档，按事实保留；本文采用当前 88/88 口径。
