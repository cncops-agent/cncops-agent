# 项目说明 · 车间设备运维 AI 智能体（只读诊断）

> 用途：路演 / 参赛 / 汇报。全文约 5 分钟讲完；每节开头加粗的一句就是该节的"台上话术"。

---

## 1. 一句话定位

**给中小加工厂的"设备医生"：操作工说一句大白话，2 秒内给出结论、证据和分级处置步骤；全程只读，绝不动设备；每次运维都沉淀成工厂自己的经验资产。**

---

## 2. 痛点（为什么值得做）

| # | 痛点 | 现场原话 | 后果 |
|---|---|---|---|
| 1 | **会说的不会修，会修的不在** | "机器不太对劲"——到底哪里不对劲？ | 小故障拖成大停机 |
| 2 | **经验锁在老师傅脑子里** | 年轻工人"不敢问、问了也记不住" | 人员流动 = 经验清零 |
| 3 | **MES 看得见、看不懂** | 屏幕上全是曲线和代码，没人告诉你该干什么 | 数据在，决策不在 |
| 4 | **聊天机器人不敢用** | 通用 AI 能聊，但会编步骤、没有安全边界 | 出一次事故就再也没人信 |
| 5 | **停机账算不清** | 老板只知道"这个月又停了两次"，不知道停在哪、多久、为什么 | 改善没有抓手 |

**市场侧写**：中国中小加工厂数十万家，设备运维高度依赖个人经验；一个数控主轴抱闸故障处理不当，一次停机损失可达数千到数万元，而一套"能说话的知识库 + 只读诊断"年费仅数千元——**ROI 一次停机就回本**。

---

## 3. 方案（我们做了什么）

### 3.1 产品形态

一个深色工业风的车间 HMI 页面（平板 / 桌面 / 手机自适应），三区同屏：

```
┌────────────────────────────────────────────────────────┐
│ 顶部状态条：一句话总览全厂（"3 台设备中 1 台报警"）        │
├──────────────┬─────────────────────────────────────────┤
│ 左侧：紧凑摘要行 │ 右侧：口语输入 + 诊断报告卡               │
│ 一行一台/56px  │  结论先行 → 证据（实测vs阈值+趋势线）      │
│ 报警自动置顶变红 │  → L1/L2/L3 分级步骤 → 安全警告           │
│ 点击行滑出详情抽屉│ （3→30 台行高字号不变，不缩放不分页）      │
├──────────────┴─────────────────────────────────────────┤
│ 历史时间线（运维台账） ｜ 经验沉淀（高频故障/复发/停机）     │
└────────────────────────────────────────────────────────┘
```

### 3.2 技术主线（固定六步，不用大模型也能跑）

```
口语解析（设备别名+同义词，确定性）
  → 取实时数据（仿真器 / OPC-UA 只读）
  → 阈值比对生成证据（报警码由"阈值+回差+去抖"推导，不写死）
  → 知识库三路检索（字面 + TF-IDF + 结构化）
  → 历史复发引用（第二次同故障主动提上次怎么处理的）
  → 固定七段格式渲染（结论/证据/原因/步骤/警告/来源/历史）
```

- **安全闸在代码里，且落在服务端**：涉及带电/高压/拆机的步骤强制升级 L3 + 安全警告，位于渲染链最后一步，**LLM 无权降级**；进入 L3 前须**勾选 LOTO 声明 + 填写持证人员姓名/工号**，由后端 `POST /api/records/{id}/l3-ack` 校验并落库留痕，绕开页面直接调接口标记该步骤完成会返回 400 且不落库。**这是人工确认，不是系统检测断电**：仿真环境未接主电源/挂锁信号，物理安全由设备侧硬回路与现场 LOTO 规程承担。
- **只读是铁律**：OPC-UA 客户端无任何写方法，有回归测试守着；故障注入只改仿真器，是受控测试夹具。
- **降级可用**：无 LLM Key / 超时 / 输出编造知识库不存在的条目 → 自动回退规则版，格式不变，**断网可演示、离线可交付**。
- **可验收**：88 项自动化自测（含新增 M 段「L3 服务端强制闸门」6 项：11 个故障逐个注入断言 Top-1、6 条误报回归、37 个阈值/报警码可达性）+ 紧凑列表/抽屉布局验收 66 项（3/10/30 台 + 手机端）+ 无头 Chrome 真实浏览器验收 + 27 项 pytest 回归（含 API 契约）。

## 4. 与 MES 及普通聊天机器人的区别

| 维度 | MES / SCADA | 普通聊天机器人（套壳 LLM） | **本项目** |
|---|---|---|---|
| 输出物 | 曲线、报表、代码 | 一段对话 | **结论 + 分级处置清单 + 安全警告** |
| 谁来用 | 工艺/IT 人员 | 任何人（但不敢信） | **操作工说人话，维修工照着做** |
| 步骤来源 | 无 | 模型即时生成（会编） | **知识库原文，每步带编号可溯源** |
| 安全边界 | 无诊断概念 | 无（可能怂恿带电作业） | **L3 强制升级 + LOTO 确认，代码级闸门** |
| 数据方向 | 只读采集 | 无设备概念 | **只读（无写方法，有测试断言）** |
| 经验沉淀 | 报表归报表 | 聊完即忘 | **每次反馈入记忆库，复发自动提醒** |
| 知识缺口 | — | 不懂也硬答 | **查不到就明说"未覆盖"，只给通用安全建议** |
| 离线可用 | 本地部署 | 依赖云端 API | **无 Key 自动降级，完全离线可跑** |

**一句话**：MES 告诉你"发生了什么事"，聊天机器人"陪你聊发生了什么"，我们告诉你"**现在该干什么、谁来干、怎么干才安全**"。

## 5. 双人轻量化模式（为小工厂的人力现实设计）

中小厂通常没有专职设备工程师，设备运维实际是**"操作工 + 维修工"两个人**兜底。系统的分级清单就是按这个现实设计的：

| 角色 | 覆盖 | 系统给什么 |
|---|---|---|
| **操作工**（开机旁） | L1 绿色步骤：查报警码、看读数、补液、清滤网、记录 | 大字步骤 + 工具/物料/耗时，戴手套能点的大按钮 |
| **维修工**（随叫随到） | L2 黄色步骤：更换件、标定、参数核对 | 同上 + 该设备历史"上次怎么修的" |
| **外部工程师**（按次付费） | L3 红色步骤：带电、高压、拆机 | 强制 LOTO 安全确认 + 完整证据包（快照+步骤勾选记录），到场即可接手 |

**轻量化体现在**：
- **部署轻**：一台平板 / 一台旧电脑 + 浏览器，无需服务器集群，无需 GPU；
- **使用轻**：说话就能诊断，无需培训；语音输入可直接用；
- **维护轻**：知识库是 YAML 文件，厂内技术员就能增删条目，不依赖厂商；
- **成本轻**：两个人 + 一个系统，覆盖 80% 常见故障，L3 才花钱请外援。

**闭环**：操作工点「已解决」→ 记录进记忆库 → 维修工下次收到复发提醒（同设备 30 天内同故障 ≥2 次自动标黄，≥3 次标红）→ 老板在经验页看停机与故障统计。**经验从个人脑子里搬到了系统里。**

## 6. 商业模式（SaaS 订阅）

**收费逻辑**：按"接入设备数 + 账号数"分档，经验沉淀与报表是续费核心（用得越久，历史数据越值钱，迁移成本越高）。

| 维度 | 免费版（获客） | 专业版（主力） | 企业版（利润） |
|---|---|---|---|
| **设备数** | ≤ 5 台 | ≤ 50 台 | 不限 |
| **账号数** | 2（操作工+维修工） | 10 | 不限 + SSO |
| **诊断** | 全功能（规则引擎） | 全功能 + LLM 增强理解 | 全功能 + 私有化 LLM |
| **知识库** | 内置条目 | **自定义知识库**（厂内技术员可维护） | 自定义 + 多品类包 |
| **历史记忆** | 30 天 | 2 年 | 不限 |
| **经验沉淀/复发提醒** | 基础统计 | **完整（高频故障/平均处理时长/停机统计/复发推送）** | 完整 + 定时报表邮件 |
| **导出** | CSV | CSV + Excel 双表 | + API / 数据仓库对接 |
| **多工厂** | 1 | 3 | 不限 + 多租户隔离 |
| **建议定价** | ¥0（演示/试用） | **¥6,800/年起** | **¥30,000/年起**（含私有化部署） |

**转化路径**：免费版用"10 秒看报警 + 结论先行"留住操作工 → 30 天历史用完时，厂长已在经验页看到停机账 → 升级专业版解锁自定义知识库与完整台账。免费→付费数据无损迁移（同一数据库加租户列，见 `docs/SAAS_PLAN.md`）。

**本阶段边界**：只做结构预留（`tenant_id`/`factory_id`/`factories` 表），**不开发支付与注册**。

## 7. 后续路线

```
现在 ──────────────► 6 个月内 ──────────────► 12–18 个月 ──────────────► 长期
仿真产线验证        半真实只读网关          多品类扩展                 生态
（已交付）          （下一步）              （注塑/冲床/压铸…）         （供应链/保险）
```

| 阶段 | 内容 | 关键动作 | 为什么是这一步 |
|---|---|---|---|
| **① 仿真（已交付）** | 3 台仿真设备、11 个故障剧本、88 项自测全绿、紧凑列表+抽屉布局 66 项验收 | 演示/参赛/试点前的信任建立 | 不碰真设备就能验证全链路；阈值与知识库可穷举自测；UI 在 3/10/30 台下行高字号不缩放已实测 |
| **② 半真实只读网关** | 接真机：OPC-UA 只读网关 + 现场 1 条产线试点 | 保持只读边界（网关侧白名单）；报警去抖按现场工况重新标定；与现有 MES 并存不冲突 | 先证明"数据是真的、结论敢用"；只读让试点零风险，厂长敢签字 |
| **③ 多品类扩展** | 注塑机、冲床、压铸机、纺织设备 | 设备点位 schema 化（现在就是按类型生成仿真值）；知识库按品类分包；L1/L2/L3 模板复用 | 单品类验证后横向复制；SaaS 分档随设备数自然增长 |
| **④ 生态（远期）** | 配件商工单对接、停机保险数据服务、二手机估值 | 停机台账数据就是议价权 | 从工具变成行业基础设施 |

**路线图原则不变**：任何阶段都保持**只读**——这是敢进车间的前提，也是和所有"要接控制系统"的方案最本质的区别。

## 8. 团队与验证（路演备用页）

- **可当场验证**：3 分钟演示脚本见 `docs/DEMO_3MIN.md`；验收截图见 `docs/screenshots/`（26 张：01–12 诊断全链路与十台/经验页 + 20–28 布局 + 29–31 反馈规则）；
  一键自测 `python tests/selftest.py`（88/88，固定种子、不污染数据）；布局验收 `python scripts/layout_check.py`（66/66）。
- **交付纪律**：结论可溯源（每步带知识库编号）、查不到明说未覆盖、危险作业 L3 强制 + 人工署名确认（服务端校验、留痕可查，非系统检测断电）、
  数据只读（代码无写方法且有测试断言）。
- **诚实的边界**：大模型增强需配置 Key（不配则规则引擎独立工作，已验收；增强模式全链路已用本地模拟服务验证，真实模型效果待真实 Key 复测）；语音输入依赖浏览器
  Web Speech API（Chrome/Edge，2026-10-25 实测：无外网环境录音正常但识别服务不可达，属环境限制）；当前设备覆盖 CNC + 空压机两类，多品类依赖第 ③ 阶段推进；**L3 安全确认是人工署名，不是设备断电检测**——只读数据源没有主电源/挂锁状态信号，系统不判断设备是否真的断电，物理安全由设备侧硬接线安全回路与现场 LOTO 规程承担，软件不替代 LOTO。
